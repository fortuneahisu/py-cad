# Contributing to Py-Cad

Thank you for your interest in contributing to this project! This is a personal learning repository, and contributions—whether bug reports, suggestions, or code improvements—are welcome.

## Code of Conduct

Please review our [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) before participating.

## How to Contribute

### Reporting Bugs

- Check existing issues to avoid duplicates
- Use the **Bug Report** issue template
- Include steps to reproduce, expected vs. actual behavior
- Specify your environment (Python version, OS, etc.)

### Suggesting Enhancements

- Use the **Feature Request** issue template
- Clearly describe the problem and proposed solution
- Explain the use case or benefit

### Submitting Code

1. **Fork** the repository
2. **Create a branch** for your changes (`git checkout -b feature/your-feature`)
3. **Make your changes** with clear, descriptive commit messages
4. **Test your changes** thoroughly
5. **Submit a Pull Request** using the PR template
   - Link any related issues
   - Describe your changes clearly
   - Note any breaking changes

## Project Structure

- **Python/** - Python scripts and experiments
- **C_C++/** - C and C++ learning projects
- **HTML_CSS_JS/** - Web development prototypes and UI experiments
- **Images/** - Reference images and diagrams

## Guidelines

- **Commits**: Write clear, concise commit messages
- **Code Style**: Follow conventions already established in the codebase
- **Comments**: Add comments for complex or non-obvious code
- **Testing**: Test your changes before submitting a PR

## Questions or Ideas?

Feel free to open a discussion issue or reach out. This is a learning space—all contributions are valued!

Thank you for contributing! 🎉
