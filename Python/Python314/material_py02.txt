------------------------------------------------------------
Section 1.8.1: Programming Mindset and Problem Decomposition
------------------------------------------------------------

Most beginners make the same mistake: they try to code immediately.

Engineers do not start with code.
They start with structure.

Problem decomposition means breaking a large problem into smaller solvable parts.

Example:
Task: Build a to-do list app

Bad approach:
- start coding random functions

Good approach:
1. Define data (what is a task?)
2. Define actions (add, remove, update, view)
3. Define storage (list, file, database)
4. Define interface (menu, CLI, UI)
5. Build each part separately

Rule:
If you cannot explain your solution in steps without code, you are not ready to code it yet.

Section 1.8.2: Debugging Fundamentals
------------------------------------------------------------

Debugging is not optional. It is the majority of programming work.

Core skills:

1. Reading error messages
   - Look at LAST line first
   - Identify error type (NameError, TypeError, etc.)
   - Locate line number

2. Print debugging
   - Insert print statements to trace values
   - Example:
     print(variable_name)

3. Step execution thinking
   - Imagine code running line by line
   - Predict output before running

4. VS Code debugger
   - Breakpoints
   - Step over
   - Step into

Rule:
If your code fails, do not rewrite everything. Trace it.

Section 1.8.5: Project Structure (Engineering-Level Code)
------------------------------------------------------------

Bad structure:
- everything in one file

Good structure:
project/
  main.py
  modules/
    logic.py
    storage.py
  data/
  README.md

Why:
- easier debugging
- reusable code
- scalable systems

Rule:
If your project cannot grow, your structure is wrong.

Section 1.8.8: Git Workflow and Commit Hygiene
------------------------------------------------------------

Git is not just storage. It is a timeline system.

Core concepts:

1. commit
   - snapshot of changes

2. push
   - send to GitHub

3. pull
   - retrieve updates

------------------------------------------------------------
Commit hygiene rules:

BAD commits:
- "final"
- "update"
- "fix"
- "new changes"

GOOD commits:
- "add task deletion feature"
- "fix null input crash in calculator"
- "refactor file input logic for clarity"

Rule:
Each commit should represent ONE logical change.

------------------------------------------------------------

Branching:
- main branch = stable version
- feature branches = experiments

Never break main branch intentionally.

Section 1.8.9: .gitignore Best Practices
------------------------------------------------------------

Always ignore:
- .vscode/
- __pycache__/

- system files

Reason:
GitHub should not store junk or local environment data.
